Inconsistent dependency lock file

Error: Inconsistent dependency lock file

The following dependency selections recorded in the lock file are
inconsistent with the current configuration:
  - provider registry.terraform.io/hashicorp/aws: required by this configuration but no version is selected

Why it happens

The configuration needs a provider that .terraform.lock.hcl has no entry for, or the lock pins a version the constraints no longer allow.

Likely causes

  • terraform init was never run in this checkout
  • A new provider or module was added
  • A version constraint was raised above the locked version

Confirm

cat .terraform.lock.hcl
grep -rn required_providers -A6 *.tf

Fix

  1. terraform init (first time or new provider)
  2. terraform init -upgrade (constraint changed), then commit the lock file

Prevent it

  • Commit .terraform.lock.hcl
  • Change constraints and run init -upgrade in the same pull request

Failed to query available provider packages

Error: Failed to query available provider packages

Could not retrieve the list of available versions for provider
hashicorp/aws: no available releases match the given constraints ~> 5.0, >= 6.0

Why it happens

No released version satisfies every constraint from the root and all modules, or the locked version no longer matches.

Likely causes

  • A module requires a newer (or older) major version than the root allows
  • The lock file pins an old version (message says: must use terraform init -upgrade)
  • A typo in the provider source

Confirm

terraform providers
cat .terraform.lock.hcl

Fix

  1. Pin the module to a release compatible with your constraint, or move the root constraint in a reviewed change
  2. terraform init -upgrade when the lock file is the only obstacle

Prevent it

  • Pin module versions
  • Upgrade provider majors deliberately, one pull request each

Provider package doesn't match the lock file checksums

Error: Failed to install provider

Error while installing hashicorp/aws v5.80.0: the current package for
registry.terraform.io/hashicorp/aws 5.80.0 doesn't match any of the
checksums previously recorded in the dependency lock file

Why it happens

The lock file has no checksum for this machine's platform, which happens when init ran through a mirror or plugin cache on another OS.

Likely causes

  • Lock file generated on macOS, CI runs Linux
  • Provider mirror records only the local platform

Confirm

cat .terraform.lock.hcl   # which h1: entries exist

Fix

  1. terraform providers lock -platform=darwin_arm64 -platform=linux_amd64 -platform=windows_amd64, then commit

Prevent it

  • Run providers lock for every platform whenever a provider version changes

Invalid for_each argument

Error: Invalid for_each argument

The "for_each" set includes values derived from resource attributes that
cannot be determined until apply

Why it happens

for_each keys must be known at plan time; IDs created in the same apply are not. A list (tuple) is also rejected: for_each needs a map or set of strings.

Likely causes

  • for_each = toset(aws_subnet.x[*].id)
  • for_each = var.list without toset()

Confirm

terraform plan

Fix

  1. Key by names written in code; keep IDs in the values
  2. Wrap lists in toset()

Prevent it

  • Plan from an empty workspace in CI to catch it early

RequestLimitExceeded or Rate exceeded during apply

Why it happens

AWS throttled the API calls and the provider gave up retrying. Part of the apply succeeded; the rest is still to do.

Likely causes

  • max_retries set very low in the provider block
  • A large apply at the default -parallelism=10
  • Other tools using the same account's API quota
